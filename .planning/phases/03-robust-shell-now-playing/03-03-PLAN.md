# Plan 03-03: Resizable Window + Pin-Aware Blur

## Objective
Window resizes, remembers its size, positions correctly at any size, and stays visible on blur when pinned.

## Context
- RESEARCH.md: `windowSize` setting is main-process-only — `isValidSetting` must keep rejecting it from renderer IPC (add explicit test).
- Depends on 03-01/03-02 only for file-conflict avoidance (createMainWindow.ts, settings.ts churn) — sequential inline execution.

## Tasks

### Task 1: windowSize setting
- `settings.ts`: add `windowSize: { width: number; height: number }` to `AppSettings`; schema `type: 'object'` with numeric properties, default `{ width: 375, height: 667 }`. Do NOT add to `isValidSetting` whitelist.
- `spec/tools/settings.spec.ts`: assert `isValidSetting('windowSize', { width: 500, height: 700 })` === false (renderer may not set it).

### Task 2: Resizable + persistence in createMainWindow
- BrowserWindow ctor: `resizable: true`; `width`/`height` from `getSetting('windowSize')` (fallback to defaults if malformed). After creation `mainWindow.setMinimumSize(300, 400)`.
- Debounced (500ms `setTimeout`/`clearTimeout`) `resize` handler → `updateSetting('windowSize', { width, height })` from `mainWindow.getBounds()`.
- Blur handler: `if (!getSetting('alwaysOnTop')) mainWindow.hide()`.

### Task 3: Live-size positioning
- `positionWindow.ts`: replace `WINDOW_WIDTH`/`WINDOW_HEIGHT` usages inside `updateWindowPosition` and `positionOnTrayClickMac` with `const [width, height] = mainWindow.getSize()`. Keep exported constants as creation defaults (rename to `DEFAULT_WINDOW_WIDTH`/`DEFAULT_WINDOW_HEIGHT` and update importers — grep first).

## Acceptance
- `npm run build` clean; all suites pass (incl. new windowSize rejection test).
- Grep: `resizable: true` and `setMinimumSize` in createMainWindow.ts; no `WINDOW_WIDTH` used inside positioning formulas (only as defaults); `getSetting('alwaysOnTop')` in blur handler.
- Conventional commits.
